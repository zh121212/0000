# 云端运行说明

用户已授权在所提供的云服务器执行完整训练。当前已连接并确认服务器有RTX 3080 Ti 12GB、Python 3.12及PyTorch 2.8.0+cu128；为本项目单独建立环境，复用现有GPU版PyTorch。实际训练是否完成以运行记录为准，不在文档中保存登录密码。

## 1. 上传什么

上传完整 `TimeXer_TaskA_Cloud` 文件夹，或解压随附ZIP。不需要上传V1、V2、conditional_hpa_v1、整个Anaconda环境或本机Node模块。

ZIP只包含两个源CSV、实际模型依赖、运行代码、单一配置和说明。云端运行时自行生成数据包、权重和结果；没有把本地未完成训练冒充云端结果。

## 2. 环境

本地使用Python 3.10和PyTorch开发版 `2.12.0.dev20260408+cu128`，这是已观测的本地环境，不是云端已验证版本。

云端优先使用已配置GPU版PyTorch的环境。若需要安装PyTorch，按[官方安装选择器](https://pytorch.org/get-started/locally/)选择与服务器系统和CUDA环境匹配的版本。本包不强制覆盖服务器已有的torch。

进入项目根目录后安装其余依赖：

```bash
python -m pip install -r requirements.txt
python -c "import torch; print(torch.__version__); print(torch.cuda.is_available())"
```

最后一项应为True，才适合执行默认GPU训练配置。requirements.txt使用本地已用过的依赖版本；云端组合仍需小样本检查，不能仅凭安装成功认定训练已验证。

## 3. 先看计划和数据

```bash
python run.py --stage plan
python run.py --stage audit
python run.py --stage prepare
```

应看到：只有任务A、七个模型、五个种子、35个正式种子结果、49次包含选参的不同训练；数据包为11,244／1,608／3,217条，输入17通道。以上操作不训练模型。

## 4. 之后再训练

等用户完成代码与流程审阅、决定开始云端训练后，在服务器执行：

```bash
python run.py --stage smoke
python run.py --stage all
```

第一条会执行256条训练样本、2轮的小检查；第二条执行全部实验，且会先校验数据和检查记录。不要同时开启多个完整队列。

需要退出SSH后继续时，可在服务器上自行选择后台工具，例如：

```bash
nohup python -u run.py --stage all > cloud_train.log 2>&1 &
```

这只是将来手动执行的示例，本地没有执行。查看进度用 `python run.py --stage status`、`cloud_train.log` 和 `03_实验结果/运行记录/worker.json`。

本次云端队列后续已按用户要求切换为最多2项并行。训练工作函数保持原样，并行调度记录在 `parallel_train.log` 和 `03_实验结果/运行记录/parallel_status.json`；其中 `active_jobs` 列出两项任务、进程和各自的轮次，独立进度文件位于 `parallel_workers/`。切换时已经运行的串行子任务继续训练，原调度父进程暂挂，全部训练完成后自动恢复它来统一测试与作图。其进程处于挂起状态是接管设计的一部分，不代表GPU子任务停止。

## 5. 暂停与重跑

前台运行时Ctrl+C会停止队列并终止当前子进程，保留已经写出的日志和最佳权重，不自动恢复。后台运行时需要按实际服务器进程管理，避免只关闭SSH却以为训练停止。

已完成且校验一致的训练可以复用。未完成项不会静默覆盖或冒充完成；它只有最佳参数，没有完整优化器状态，需先保留和移出该未完成运行目录，再重新开始该项，不能当作精确断点续训。

配置或代码改变时不混用旧数据包、旧权重和旧指标。不同PyTorch版本、设备和运行环境可能有数值差异，云端整组重新运行并保存实际环境记录更便于解释。

## 6. 下载什么结果

至少保存并下载：

- `03_实验结果/01_对比实验/统一结果表.csv`：同一表格中的五次结果、均值、样本标准差及保持不变参考。
- 各运行目录的权重、日志、result.json、test_metrics.json和test_predictions.csv。
- `03_实验结果/运行记录`：实际版本、状态和选参记录。
- `01_数据集/03_划分打包/packing_audit.json`及标准化参数：用于核对数据版本和时间划分。

CSV可直接用Excel打开。云端不需要安装本地的表格生成插件；后续需要论文排版用的Excel表时，可由这些真实结果统一转换。
