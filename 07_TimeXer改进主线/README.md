# 当前数据集上的TimeXer主线改进

这一目录只包含新增文件，原工程（`02_训练流程`、`04_实验配置`、数据包、v1结果）一个字节都不改。七个基线不重训，直接复用v1结果。

**本轮范围：先训练主方案 `TimeXer_LA_PD_C3Raw`，共7次正式训练，最终报告五种子。** 原TimeXer与已经完成的LA、LA_PD作为严格复现后的参照。其余消融、新站点、门控不在本轮启动，不计算新测试成绩。

## 改了什么

模型主干是原TimeXer，原样调用。只在外面加了三个组件，都在 `timexer_variants.py` 里，都不增加可训练参数：

| 组件 | 解决的问题 | 位置 |
|---|---|---|
| LastAnchor（LA） | 输出以窗口均值为参照，水位一变化就滞后 | 输出端：原预测 + (最后实测水位 − 窗口均值) |
| 控制细节标记（C3Raw） | 本站流量和开度的短时变化没被用上 | 输入端：目标站流量和各孔开度最近3步去均值，并入TimeXer已有的时间输入，经交叉注意力读取 |
| 外部通路免衰减（PD） | 权重衰减把外部信息通路压到几乎为0 | 训练端：外部嵌入和交叉注意力的参数不衰减，其余参数仍为1e-4 |

下面七个变体用于后续完整消融；当前只先训练V4，不同时启动全部变体：

| 编号 | 变体 | 回答的问题 |
|---|---|---|
| V0 | TimeXer | 基线（复用v1） |
| V1 | TimeXer_PD | 不改参照时，免衰减本身有没有用 |
| V2 | TimeXer_LA | 改参照有没有用 |
| V3 | TimeXer_LA_PD | 两者叠加 |
| V4 | TimeXer_LA_PD_C3Raw | **主方案候选** |
| V5 | TimeXer_LA_PD_C3Zero | 控制标记全填0：收益是不是只因为多了3个输入位置 |
| V6 | TimeXer_LA_PD_C3Norm | 控制标记按窗口归一化：保留变化幅度是否必要 |
| V7 | TimeXer_LA_C3Raw | 外部通路照常衰减时，控制标记还有没有用 |

共同条件为同一数据包和划分、MSE损失、Adam、batch64、dropout0.1、最多100轮、patience10；种子42试3个学习率，按验证RMSE选定，再补4个种子。PD明确改变外部通路的衰减设置，不能称全部训练设置完全相同。完整消融是49次，本轮主方案只需7次。

## 运行顺序

在项目根目录（`TimeXer_TaskA_Cloud`）打开PowerShell，按顺序执行。Python路径按你本机的环境：

```powershell
$py = 'D:/anaconda3/envs/rl_case1/python.exe'
& $py -B -X utf8 -u 07_TimeXer改进主线/run_improvement.py --stage main --device cuda --parallel 2
```

此命令会核对计划与自检，训练主方案7次并输出验证汇总；不会启动49次完整消融。最优学习率的种子42结果直接计入最终五种子，不重复训练。若需要降低资源占用可用 `--parallel 1`，不改变模型与超参数。

输出见 `03_实验结果/12_TimeXer改进主线/当前主线结果.md` 和 `当前主线对比.csv`；进度见 `active_phase.json`、`progress.json`。后续明确执行完整消融时，运行 `--stage fit`（不带 `--models`）会复用本轮任务并补足49次，随后才执行 `evaluate`、`judge`。完整消融未完成时，`judge`会拒绝输出组件结论。

本轮不执行 `freeze` 或 `test`。完整消融与选型结束后才进入以下阶段，不能提前用其结果指导本轮选择：

```powershell
& $py -X utf8 07_TimeXer改进主线/run_improvement.py --stage freeze     # 6. 冻结方案
& $py -X utf8 07_TimeXer改进主线/run_improvement.py --stage test       # 7. 开发测试集评估（只能执行一次）
```

只想先检查代码能不能跑通，可以单独运行随机输入测试，不读数据、不训练：

```powershell
& $py -X utf8 07_TimeXer改进主线/forward_test.py
```

## 每一步做什么

1. **plan**：把变体清单、判据、主方案选择规则写入 `plan.json`。写入后不能再改，防止看到结果后调整标准。
2. **selftest**：
   - 随机输入Forward Test：7个变体在任务A（17通道）和一个假想4孔站点（19通道）上前向、反向，检查形状、梯度、输入未被改动；检查LA在头部输出为0时等于最后实测值、控制标记的数值性质、参数分组无重复无遗漏、错误输入会给中文报错。
   - 组件全关的变体与原TimeXer逐样本一致。
   - 35个基线权重：哈希一致，重新推理的验证RMSE与v1记录一致，才允许复用。
   - 用新代码加载06、08、11轮的旧权重，验证集预测与旧记录一致（差小于1e-6 m），证明新代码与之前的实验是同一个模型。
   - 每个变体用256条样本训练2轮，检查参数分组的衰减值、预测会变化、保存后能严格重载。
3. **fit**：完整清单共49次；使用 `--models TimeXer_LA_PD_C3Raw` 时只运行主方案7次。结果写入 `03_实验结果/12_TimeXer改进主线/training`。重复运行会校验并复用已完成任务；未完成或失败的现场保留，不自动覆盖、删除或盲目重试。
4. **evaluate**：只算训练集和验证集，输出 `验证集均值.csv`，并记录交叉注意力权重相对初始化的范数，用来观察免衰减是否让外部通路恢复。
5. **judge**：仅完整消融完成后按 `plan.json` 判定组件作用并选型。本轮先行训练不作完整组件结论，D8/H1留待后续；“暂不启动门控”不表示诊断已经否定它。
6. **freeze**：记录代码和全部权重的哈希。之后代码或权重有任何改动，第7步会拒绝运行。
7. **test**：评估开发测试集一次，给出与七个基线的对比、按天分块bootstrap区间、DM检验（Holm校正）。

## 出错时怎么办

- 报错信息都是中文，会写明哪一步、哪个形状或哪个文件不一致。把完整报错发给我。
- 如果是新组件的问题，只改 `timexer_variants.py`；原训练代码不动。改完要重新运行 `selftest`（已训练的结果会因版本指纹变化而不能复用，这是有意的）。
- 如果 `selftest` 的复现检查失败，不要开始训练，先把报错发给我。

## 使用主方案预测

训练完成后可用固定演示种子42预测现有验证包，输出水位单位m：

```powershell
& $py -B -X utf8 07_TimeXer改进主线/predict_improved.py --seed 42
```

结果为 `03_实验结果/12_TimeXer改进主线/使用预测_seed42.csv`。五个种子分别保存，不作预测集成。可用 `--input 文件.npz` 输入按原字段顺序、训练标准化和日历编码组织的x[B,12,17]，不会重新拟合标准化参数。已有输出不覆盖，可用 `--output 新路径.csv`。

## 与完整实验计划的范围区别

完整计划还有消融、扩展模型和新站点。本轮按用户要求先完成现有任务A的主方案。工程上复用本目录的独立入口导入原 `train.py`，仅在隔离训练进程中接入新模型和Adam参数组，原文件完全不动；退出时恢复Adam引用。权重衰减差异明确记入运行记录，不把本轮初步结果称为完整论文证据。
